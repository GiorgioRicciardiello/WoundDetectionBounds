# Wound Healing Verification App

Interactive web-based interface for reviewing and validating wound segmentation results.

## Quick Start

```bash
# Basic launch (assumes segmentation is already done)
python run_verification_app.py

# Run segmentation first, then launch app
python run_verification_app.py --run-segmentation

# Use a custom port
python run_verification_app.py --port 8080
```

Then visit: **http://localhost:5000** in your browser

## Overview

The verification app provides a user-friendly interface to:

### ✅ Review Segmentation Quality
- View t=0 (initial timepoint) raw images alongside model predictions
- QC indicators show which images passed/failed automated quality checks
- Organize by experiment, condition, and sample

### ✅ Annotate Results
- Mark segmentations as **correct** or **incorrect**
- Add optional notes for each image
- Session auto-saves as you review

### ✅ Compute Accuracy Metrics
- Draw manual polygons on images to create ground-truth masks
- Compare against model predictions
- Metrics computed: Dice coefficient, IoU, precision, recall, F1-score
- Identify systematic biases in your model

### ✅ Edge Correction Mode
- Fine-tune wound boundaries with point-and-click interface
- Correct upper/lower wound edges independently
- Re-compute metrics after corrections

### ✅ Export Results
- Download verification annotations as Excel file
- Includes model predictions, manual annotations, metrics, and notes
- Batch export with timestamps

## Requirements

### Software
- Python 3.11+
- Flask (install with: `pip install flask`)
- All dependencies from project environment (NumPy, Pillow, pandas, etc.)

### Data
1. **Configuration file** (`config.yaml`)
   - Must point to valid `experiments.xlsx` with image paths
   - Output directory must be writable

2. **Segmentation results** (`trajectories.pickle`)
   - Generated by running: `python main.py`
   - Located in: `<output_dir>/segmentation/trajectories.pickle`

## Usage Guide

### 1. Basic Launch

```bash
python run_verification_app.py
```

**What it does:**
- ✓ Checks Python dependencies
- ✓ Validates config.yaml
- ✓ Verifies segmentation results exist
- ✓ Launches Flask web server
- ✓ Opens at http://localhost:5000

**Exit:** Press `Ctrl+C` in terminal to stop

### 2. Run Segmentation + Verification

```bash

```

**What it does:**
- ✓ Checks config.yaml
- ✓ Runs full quantification segmentation pipeline
- ✓ Saves results to `trajectories.pickle`
- ✓ Automatically launches verification app

**Note:** This may take 10-30 minutes depending on image count and CPU cores.

### 3. Custom Port

```bash
python run_verification_app.py --port 8080
```

**Access at:** http://localhost:8080

**Why?** Default port 5000 might conflict if running multiple services.

### 4. Debug Mode

```bash
python run_verification_app.py --debug
```

**Features:**
- Auto-reload when code changes
- Detailed error messages
- Verbose logging
- **Warning:** Slower performance, not for production

## Web Interface

### Main Page

**Left Panel (Image List)**
- Filterable table of all t=0 images
- Columns: trajectory key, condition, experiment, sample, QC status, annotation status, Dice score
- Click row to view full image

**Center Panel (Image Viewer)**
- Raw grayscale image
- Model prediction mask overlay
- Zoom and pan controls
- Mode selector (review / annotate / edge correct)

**Right Panel (Annotation)**
- Verdict: Mark as correct/incorrect/unsure
- Notes field for observations
- Polygon drawing area (if in annotate mode)
- Computed metrics display

### Review Mode
- View raw image and model mask side-by-side
- Quick verdict buttons: ✓ Correct, ✗ Incorrect, ? Unsure
- Session auto-saves

### Annotate Mode
- Draw manual polygons on the image
- Right-click to start polygon, left-click to add vertices, double-click to close
- Computed metrics (Dice, IoU, precision, recall) displayed in real-time
- Metrics saved with annotation

### Edge Correction Mode
- View model's upper and lower wound edges as lines
- Correct edges by clicking to adjust boundary points
- Useful when model slightly mis-detects boundary
- Re-compute metrics from corrected edges

### Export Mode
- Generate Excel file with all annotations and metrics
- Filename: `verification_results_YYYYMMDD_HHMMSS.xlsx`
- Contains: metadata, verdicts, polygon vertices, metrics, notes

## Configuration

### config.yaml Requirements

```yaml
# MUST exist and point to valid Excel file
input_excel: "path/to/experiments.xlsx"

# Output directory for segmentation results
output:
  base_dir: "path/to/output"
  segmentation_subdir: "segmentation"  # Relative to base_dir

# Column mappings (must match your Excel headers)
columns:
  image_path: "image_path"           # Column with full path to .tif images
  time_min: "time_min"               # Column with timepoint in minutes
  condition: "sample_condition"      # Treatment group (DMSO, Alk5i, etc.)
  experiment: "experiment"           # Batch (EXP1, EXP2)
  sample_name: "sample_name"         # Sample identifier
  factors:
    - name: "cell_line"
      column: "cell_line"
```

### Key Paths

| File | Purpose | Location |
|------|---------|----------|
| `config.yaml` | Pipeline configuration | Root directory |
| `experiments.xlsx` | Sample metadata + image paths | Referenced in config.yaml |
| `trajectories.pickle` | Segmentation results | `<base_dir>/segmentation/` |
| `verification_session.json` | Annotation progress | `<base_dir>/segmentation/` (auto-created) |
| Exports | Excel files with results | `<base_dir>/segmentation/` |

## Troubleshooting

### "Flask not installed"
```bash
pip install flask
# or activate conda environment:
conda activate imgai_env
```

### "Config file not found"
- Copy from example: `cp config.example.yaml config.yaml`
- Edit paths to point to your data

### "Segmentation not found"
- Run: `python main.py`
- Or use: `python run_verification_app.py --run-segmentation`

### "Port already in use"
```bash
# Use different port:
python run_verification_app.py --port 8080
```

### "Session corrupted or lost"
- Delete `verification_session.json` in output directory
- Start fresh (old annotations are discarded)

### App crashes or doesn't load images
1. Check browser console (F12 → Console tab) for JS errors
2. Check terminal for Python errors
3. Verify `trajectories.pickle` is not corrupted: `python -c "import pickle; pickle.load(open('path/to/trajectories.pickle', 'rb'))"`

## Data Format

### Input: experiments.xlsx

Minimum required columns:
```
| image_path | time_min | sample_condition | experiment | sample_name |
|------------|----------|------------------|------------|-------------|
| /path/to/img1.tif | 0 | DMSO | EXP1 | b1_s1 |
| /path/to/img2.tif | 6 | DMSO | EXP1 | b1_s1 |
| /path/to/img3.tif | 0 | Alk5i | EXP1 | b2_s2 |
| ... | ... | ... | ... | ... |
```

### Output: trajectories.pickle

Binary pickle file containing:
```python
{
    "trajectory_key_1": {
        "results": [
            {
                "img_raw": np.ndarray,      # Raw grayscale image (H, W)
                "mask": np.ndarray,         # Binary wound mask (H, W)
                "upper_edge": np.ndarray,   # Upper wound boundary (W,)
                "lower_edge": np.ndarray,   # Lower wound boundary (W,)
                "qc": {"valid": bool, ...}  # QC metrics
                "file_name": str,           # Source image path
            },
            # ... more timepoints (t=1, t=2, ...)
        ],
        "exposure": str,                    # Treatment condition
        "experiment": str,                  # Experiment batch
        "sample_name": str,                 # Sample ID
    },
    # ... more trajectories
}
```

### Export: verification_results_*.xlsx

Excel workbook with sheets:

**Sheet: "Annotations"**
- trajectory_key, original_filename, condition, experiment, sample
- correct (True/False/null), notes, dice_score, iou, precision, recall, f1

**Sheet: "Summary"**
- Aggregate statistics by condition/experiment
- Count of correct/incorrect/unsure annotations
- Mean metrics by group

## Metrics Explained

When you draw a manual polygon and compare against the model mask:

| Metric | Formula | Interpretation |
|--------|---------|-----------------|
| **Dice** | 2·TP/(2·TP + FP + FN) | Overlap (0-1, 1=perfect) |
| **IoU** | TP/(TP + FP + FN) | Intersection over union (0-1) |
| **Precision** | TP/(TP + FP) | Of predicted pixels, how many are correct |
| **Recall** | TP/(TP + FN) | Of true pixels, how many were found |
| **F1** | 2·precision·recall / (precision + recall) | Balanced score |

- TP = True positives (wound pixels correctly identified)
- FP = False positives (non-wound pixels incorrectly marked as wound)
- FN = False negatives (wound pixels missed by model)

## Session Management

### Auto-Save
- Annotations are saved to disk after every change
- File: `verification_session.json` in segmentation output directory
- You can close browser anytime and resume later

### Resume Session
1. Run: `python run_verification_app.py`
2. Previous annotations will be loaded automatically
3. Continue reviewing from where you left off

### Reset Session
- Delete `verification_session.json` in output directory
- Next launch will start with blank annotations

### Backup Session
```bash
# Copy your progress before major changes:
cp <output_dir>/segmentation/verification_session.json <output_dir>/segmentation/verification_session_backup.json
```

## Performance Tips

### Large Datasets (1000+ images)
- Use `--port 8080` to ensure dedicated port
- Consider splitting into smaller batches for review
- Don't zoom/pan too aggressively in browser

### Slow Network (VPN/Remote)
- Increase image load timeout in browser settings
- Reduce image resolution (edit config to skip debug PNGs)

### Batch Operations
- Use bulk-approve/bulk-reject buttons (bottom of app)
  - Approve all QC-valid images at once
  - Reject all QC-invalid images at once
- Then manually review edge cases

## Architecture

### Server Side (Python/Flask)
- `library/verification/app.py` — Flask application and routes
- `library/verification/data_loader.py` — Load trajectories.pickle
- `library/verification/metrics.py` — Compute Dice, IoU, etc.
- `library/verification/export.py` — Generate Excel exports

### Client Side (HTML/JavaScript)
- `library/verification/templates/index.html` — Single-page app
- `library/verification/static/app.js` — React-like state management
- `library/verification/static/style.css` — Styling (responsive, dark mode)

### Data Flow
```
trajectories.pickle
        ↓
   load_master_trajectories()
        ↓
   extract_t0_records()  (only t=0 images)
        ↓
   [Server: Records indexed by trajectory_key]
        ↓
   [Browser: Load via /api/records endpoint]
        ↓
   [User: Annotate images]
        ↓
   [POST /api/annotate]  → verification_session.json
        ↓
   [Export to Excel]
```

## Known Limitations

1. **Single-timepoint review**: Only t=0 images shown (by design for efficiency)
2. **Polygon limitation**: Max 100 vertices per polygon (for performance)
3. **Browser compatibility**: Works best on Chrome, Firefox, Safari (Edge supported)
4. **File size**: trajectories.pickle >2GB may cause memory issues
